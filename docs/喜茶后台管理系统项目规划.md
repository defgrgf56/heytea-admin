| 项目 | 内容 |
|---|---|

## 1. 文档目的

本文档用于统一喜茶后台管理系统的产品范围、页面结构、角色权限、业务规则、接口需求、数据模型、研发阶段和验收标准。

项目目标不是建设完整商业商城平台，而是在可控规模内形成一套结构完整、接口真实、权限清晰、业务闭环成立的后台管理系统。

本文档是后续前端开发、后端接口开发、联调、测试和验收的共同依据。接口字段和响应示例应在正式开发时进一步沉淀到独立 API 对接文档中。

## 2. 项目定位

系统由用户端、后台管理端和独立 API 服务组成：

- `heytea-website`：面向普通用户，负责注册登录、商品浏览、购物车、地址维护和订单查询。
- `heytea-admin`：面向后台工作人员，负责商品、分类、订单、用户、门店和系统权限管理。
- `frontend-lab-api`：提供独立业务接口、认证、权限校验、数据存储和文件上传能力。

后台与用户端使用同一套茶饮业务数据。后台修改商品、门店或订单状态后，用户端应能够读取到最新结果。

本系统不承载真实商业交易，不接入真实支付、退款、结算和物流平台。

## 3. 当前项目基线

当前项目已经具备以下基础：

- Vue 3 + Vite 项目结构。
- Element Plus 基础组件库。
- Vue Router 路由框架。
- Pinia 用户状态管理。
- Axios 请求封装。
- ECharts 图表依赖。
- 登录页和后台主布局。
- 工作台页面骨架。
- 商品列表和编辑页面。
- 分类管理页面。
- 订单列表和详情页面。
- 用户列表和详情页面。
- 门店列表和编辑页面。
- 收货地址列表页面。
- 基础分页、筛选、弹窗和表单交互。

当前仍存在以下关键缺口：

- 开发环境无条件使用 Mock 登录，无法使用真实管理员身份访问线上接口。
- 真实登录直接提交账号和密码，未实现 RSA Challenge 加密协议。
- Token 刷新方法存在，但请求层没有自动刷新和并发重试机制。
- 页面刷新时只恢复本地用户信息，没有通过服务端验证当前会话。
- 工作台统计、趋势、分布和排行全部为静态数据。
- 商品表单字段与现有后端字段不统一。
- 商品分类选择项写死，未读取分类接口。
- 商品图片仅支持填写 URL，未实现统一上传。
- 分类、订单、用户、门店和地址管理接口尚未在后端实现。
- 侧栏菜单完全由静态路由生成，没有菜单权限。
- 页面和按钮没有权限码控制。
- 缺少后台管理员、角色、菜单和操作日志页面。
- 缺少 `403`、`404` 和统一异常页面。
- 缺少测试、Lint、权限工具和正式生产环境配置。

当前页面可以作为后续开发基础，不需要推倒重做，但认证、字段契约和权限体系需要优先调整。

## 4. 建设目标

最终系统应达到以下效果：

1. 管理员能够通过加密登录进入后台。
2. 系统能够根据管理员角色返回不同菜单。
3. 页面能够根据权限码控制操作按钮。
4. 后端能够对每个管理接口执行权限校验。
5. 商品、分类、订单、用户和门店均使用真实数据库数据。
6. 工作台使用真实统计接口和图表数据。
7. 后台操作能够同步影响用户端展示和订单状态。
8. 重要写操作能够自动记录操作日志。
9. 所有列表具备分页、筛选、排序、加载、空状态和错误处理。
10. 系统具备基本测试、构建和部署能力。

## 5. 非建设范围

- 多租户和多商户 SaaS。
- 部门、岗位和组织机构管理。
- 数据范围权限和行级权限。
- 审批流和工作流引擎。
- 真实微信支付和支付宝支付。
- 真实退款、对账和财务结算。
- 发票系统。
- 仓库、采购和供应链系统。
- 复杂优惠券、会员积分、拼团和秒杀。
- 短信验证码和消息推送平台。
- 实时物流轨迹。
- 复杂操作审计和安全分析平台。

## 7. 角色设计

系统预置四个角色，后续可通过角色管理新增其他角色。

### 7.1 超级管理员 `SUPER_ADMIN`

- 拥有全部菜单和按钮权限。
- 可以管理后台管理员、角色和菜单。
- 不能被普通管理员编辑、禁用或删除。
- 系统必须始终保留至少一个启用状态的超级管理员。

### 7.2 商品运营 `PRODUCT_OPERATOR`

- 查看工作台。
- 查看、新增和编辑商品。
- 上架、下架和设置售罄。
- 维护商品分类。
- 无权删除管理员和配置系统角色。

### 7.3 订单客服 `ORDER_SERVICE`

- 查看工作台。
- 查看用户基础资料。
- 查看订单列表和详情。
- 按规则推进或取消订单。
- 无权编辑商品和管理系统权限。

### 7.4 门店管理员 `STORE_MANAGER`

- 查看工作台。
- 查看、新增和编辑门店。
- 调整门店营业状态。
- 无权管理商品、订单和系统权限。

## 8. 权限模型

权限分为菜单权限和操作权限。

菜单权限决定管理员能否看到并进入某个页面。操作权限决定管理员能否执行页面内的新增、编辑、删除、上下架、状态更新、导出等操作。

权限码统一使用 `资源:动作` 格式，例如：

- `dashboard:view`
- `product:view`
- `product:create`
- `product:update`
- `product:delete`
- `product:publish`
- `category:view`
- `category:manage`
- `order:view`
- `order:update`
- `order:export`
- `customer:view`
- `customer:update`
- `customer:export`
- `store:view`
- `store:create`
- `store:update`
- `store:delete`
- `staff:view`
- `staff:manage`
- `role:view`
- `role:manage`
- `menu:view`
- `menu:manage`
- `operation-log:view`

权限控制必须同时落实在三个位置：

1. 后端根据 Token、角色和权限码校验接口访问。
2. 前端路由守卫阻止进入无权页面。
3. 前端按钮权限指令隐藏或禁用无权操作。

前端隐藏菜单和按钮只用于改善操作体验，不替代后端权限校验。

## 9. 菜单模型

菜单使用树形结构，节点类型分为：

- `DIRECTORY`：目录，只用于菜单分组。
- `MENU`：页面菜单，对应一个前端页面。
- `BUTTON`：操作权限，不对应路由。

菜单字段至少包含：

- 菜单 ID。
- 父菜单 ID。
- 菜单名称。
- 菜单类型。
- 路由名称。
- 路由路径。
- 前端组件标识 `componentKey`。
- 图标名称。
- 权限码。
- 排序值。
- 是否隐藏。
- 启用状态。

后端只返回组件标识，前端使用固定组件映射表加载页面，不允许后端返回任意本地文件路径。

目录或菜单存在子节点时不能直接删除。停用菜单后，新登录用户不再获得该菜单；按钮节点停用后，对应权限不再下发。

## 10. 认证与会话逻辑

### 10.1 登录流程

1. 前端请求一次性登录 Challenge。
2. 后端返回 `challengeId`、`nonce`、RSA 公钥和过期时间。
3. 前端使用 `RSA-OAEP-SHA256` 加密登录数据。
4. 前端提交 `credential.challengeId` 和密文 `credential.payload`。
5. 后端解密并校验管理员账号、密码和状态。
6. 后端返回 JWT、当前管理员、角色和权限码。
7. 前端保存会话并请求当前用户菜单。
8. 前端注册允许访问的动态路由并进入工作台。

Challenge 只能使用一次，并设置短有效期。登录接口不能接受普通明文密码请求体。

### 10.2 会话恢复

页面刷新后，前端读取本地 Token，但必须调用当前用户接口确认 Token 有效，并重新获取角色、权限和菜单。

### 10.3 Token 刷新

请求层应在 Token 即将过期或收到可刷新的认证错误时请求新 Token。同一时间只允许发起一个刷新请求，其他请求等待刷新完成后重试。

刷新失败时清理会话并跳转登录页。登录和退出接口不参与自动刷新。

### 10.4 退出登录

退出时先调用服务端退出接口，使当前 Token 失效，再清理本地 Token、用户、权限和动态路由。

## 11. 工作台规划

### 11.1 数据概览

展示以下指标：

- 今日订单数。
- 今日销售额。
- 待处理订单数。
- 上架商品数。
- 注册用户数。
- 营业门店数。

### 11.2 销售趋势

支持最近 7 天、最近 30 天和自定义日期范围。图表展示日期、订单数和销售额。

### 11.3 订单状态分布

展示待支付、已确认、制作中、配送中、已完成和已取消订单数量。

### 11.4 热销商品

展示商品名称、分类、销量、销售额和排行。

### 11.5 最近订单

展示最近创建的订单号、用户、金额、状态和下单时间，并支持进入订单详情。

工作台每个区域应具备独立加载状态、空状态和失败重试，不因单个接口失败导致整页不可用。

## 12. 商品管理规划

### 12.1 商品列表

支持以下查询条件：

- 商品名称关键词。
- 商品分类。
- 商品状态。
- 是否新品。
- 是否热销。
- 创建时间。
- 价格或创建时间排序。

支持分页、重置筛选、进入详情、新增、编辑、删除、上下架、售罄和批量状态调整。

### 12.2 商品字段

统一使用以下字段：

- `name`：中文名称。
- `nameEn`：英文名称。
- `description`：中文描述。
- `descriptionEn`：英文描述。
- `price`：商品价格。
- `categoryCode`：分类编码。
- `imageUrl`：商品图片地址。
- `stock`：库存。
- `status`：`ON_SALE`、`OFF_SALE`、`SOLD_OUT`。
- `isNew`：是否新品。
- `isHot`：是否热销。
- `sortOrder`：展示顺序。
- `specs`：商品规格。

禁止继续混用 `desc/description`、`category/categoryCode`、`image/imageUrl` 和 `sort/sortOrder`。

### 12.3 商品规格

规格包括杯型、甜度和加料：

- 杯型包含编码、名称和加价。
- 甜度包含编码和名称。
- 加料包含编码、名称和价格。

前端使用动态表单维护规格项，至少保留一个有效杯型。规格编码在同一商品内不能重复。

### 12.4 商品图片

商品图片通过统一上传接口上传。前端校验文件格式和大小，展示上传进度、预览和失败提示。数据库只保存服务端返回的 HTTPS URL。

### 12.5 商品业务规则

- 商品名称、价格和分类必填。
- 价格不能为负数。
- 库存不能为负数。
- 分类必须存在且可用。
- 库存为零时允许设置为 `SOLD_OUT`。
- 下架商品不能出现在公开商品列表中。
- 已被历史订单引用的商品删除后，订单商品快照仍然保留。

## 13. 商品分类规划

分类字段包括编码、中英文名称、图标、排序、状态、商品数量和创建时间。

业务规则如下：

- 分类编码唯一，创建后不允许修改。
- 启用分类可以用于商品创建和编辑。
- 禁用分类不再出现在商品分类选择器中。
- 分类下存在商品时不允许直接删除。
- 排序值越小越靠前。
- 分类状态和排序修改失败时，前端恢复原值。

## 14. 订单管理规划

### 14.1 订单列表

支持订单号、用户名、手机号、订单状态和下单日期范围筛选，支持分页和创建时间排序。

### 14.2 订单详情

展示以下内容：

- 订单号和创建时间。
- 当前状态和支付方式。
- 用户名称和联系电话。
- 收货地址。
- 商品名称、图片、规格、单价、数量和小计。
- 商品总额、配送费和实付金额。
- 状态处理记录。

订单商品必须保存下单时快照。后续修改商品名称、图片或价格不能改变历史订单。

### 14.3 订单状态

订单状态为：

- `PENDING`：待支付。
- `CONFIRMED`：已确认。
- `PREPARING`：制作中。
- `DELIVERING`：配送中。
- `COMPLETED`：已完成。
- `CANCELLED`：已取消。

正常流转为：待支付到已确认、已确认到制作中、制作中到配送中、配送中到已完成。

待支付、已确认或制作中的订单可以按规则取消。已完成和已取消订单不能继续修改状态。后端负责校验状态流转，前端只展示当前可执行的操作。

## 15. 用户管理规划

用户管理对象是用户端注册顾客，不是后台管理员。

### 15.1 用户列表

支持用户名、昵称、邮箱和手机号搜索，支持状态、标签和注册时间筛选。

### 15.2 用户详情

展示基础资料、账号状态、标签、注册时间、最后登录时间、订单数量、累计消费金额、历史订单和收货地址。

### 15.3 用户操作

- 启用或禁用账号。
- 添加或移除用户标签。
- 查看历史订单。
- 查看消费统计。
- 查看收货地址。
- 导出当前筛选结果。

用户不进行物理删除。禁用用户不能继续登录，但历史订单、地址和统计数据仍然保留。

后台不直接使用简单弹窗提交明文新密码。需要密码重置时，使用安全临时密码流程或单独的加密重置协议。

## 16. 收货地址规划

收货地址主要在用户详情内展示。可保留地址查询页面作为用户管理子页面，用于按用户、省份和城市检索。

地址包含收件人、联系电话、省、市、区、详细地址、标签、默认状态和创建时间。

后台默认只读。只有具备专门权限的管理员才允许删除明显错误或违规地址，删除操作必须记录日志。

## 17. 门店管理规划

### 17.1 门店列表

支持门店名称、城市和营业状态筛选，支持分页、进入编辑、状态调整和删除。

### 17.2 门店字段

- 门店名称。
- 门店图片。
- 省、市、区。
- 详细地址。
- 经度和纬度。
- 联系电话。
- 营业开始时间。
- 营业结束时间。
- 门店状态。
- 服务特色。
- 停车说明。

### 17.3 门店状态

- `OPEN`：营业中。
- `CLOSED`：已关闭。
- `MAINTENANCE`：维护中。

用户端只展示允许公开且未删除的门店，并根据状态展示是否营业。

## 18. 管理员管理规划

后台管理员与前台顾客在业务概念上分离。

管理员页面支持：

- 管理员列表和关键词搜索。
- 新增管理员。
- 编辑昵称、邮箱和头像。
- 启用或禁用账号。
- 分配一个或多个角色。
- 重置登录密码。
- 查看最后登录时间。

业务规则如下：

- 登录名唯一且创建后不可随意修改。
- 管理员不能禁用自己。
- 普通管理员不能编辑超级管理员。
- 至少保留一个启用状态超级管理员。
- 禁用管理员后，其未过期 Token 应立即失效。
- 管理员角色变更后，其权限缓存和会话权限应及时更新。

## 19. 角色管理规划

角色字段包括名称、编码、说明、状态、排序、菜单权限、操作权限和创建时间。

角色页面支持：

- 角色列表。
- 新增和编辑角色。
- 启用和禁用角色。
- 删除未被使用的角色。
- 使用树形控件配置菜单和按钮权限。

系统内置超级管理员角色不可删除。角色被管理员引用时不允许直接删除。

## 20. 菜单管理规划

菜单页面使用树形表格展示目录、页面和按钮。支持新增子节点、编辑、启停、排序和删除。

新增或编辑菜单时，根据菜单类型显示不同字段：

- 目录：名称、图标、父级、路径、排序和状态。
- 菜单：名称、父级、路由名称、路径、组件标识、图标、权限码、排序和状态。
- 按钮：名称、父级、权限码、排序和状态。

菜单修改后，新登录会话使用最新菜单。当前会话可以通过重新获取权限刷新菜单。

## 21. 操作日志规划

后端通过统一中间件自动记录重要操作，不依赖前端主动上报。

记录范围包括：

- 登录和退出。
- 新增、编辑和删除商品。
- 商品状态和批量状态变更。
- 分类新增、编辑、状态、排序和删除。
- 订单状态变更。
- 用户启停和标签变更。
- 门店新增、编辑、状态和删除。
- 管理员、角色和菜单变更。
- 用户和订单数据导出。

日志字段至少包含管理员、角色、模块、操作类型、请求方法、接口路径、目标资源、操作结果、错误信息、IP、User-Agent 和操作时间。

日志页面支持管理员、模块、操作类型、结果和时间范围筛选。日志只允许查询和查看详情，不提供前端删除功能。

## 22. 文件上传规划

提供统一图片上传接口，商品、门店和管理员头像复用同一接口。

上传约定：

- 请求格式为 `multipart/form-data`。
- 文件字段名为 `file`。
- 支持 `jpg`、`jpeg`、`png` 和 `webp`。
- 单文件最大 2 MB。
- 后端校验 MIME 类型和文件内容。
- 后端生成安全文件名，不直接使用用户文件名作为存储路径。
- 成功后返回 HTTPS URL、原文件名、文件大小和 MIME 类型。

## 23. 统一接口规范

### 23.1 成功响应

```json
{
  "success": true,
  "message": "操作成功",
  "data": {}
}
```

### 23.2 失败响应

```json
{
  "success": false,
  "message": "分类下仍有关联商品，不能删除",
  "code": "CATEGORY_IN_USE",
  "details": null
}
```

### 23.3 分页响应

```json
{
  "success": true,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "pageSize": 20,
    "total": 0,
    "totalPages": 0
  }
}
```

### 23.4 分页参数

- `page`：默认 `1`，最小 `1`。
- `pageSize`：默认 `20`，最大 `100`。
- `keyword`：关键词。
- `sortBy`：排序字段。
- `sortOrder`：`asc` 或 `desc`。

### 23.5 HTTP 状态码

- `200`：查询或更新成功。
- `201`：创建成功。
- `400`：请求格式错误。
- `401`：未登录、Token 无效或已失效。
- `403`：已登录但无权限。
- `404`：资源不存在。
- `409`：资源冲突或业务状态冲突。
- `422`：字段校验失败。
- `429`：请求过于频繁。
- `500`：服务端异常。

## 27. 安全要求

- 所有公网请求使用 HTTPS。
- 登录和密码操作使用一次性 RSA Challenge。
- 数据库只保存密码哈希，不保存明文或可逆密码。
- Challenge 一次有效并设置短过期时间。
- 登录失败次数达到阈值后短暂锁定账号。
- 所有管理接口校验管理员状态和权限。
- 管理员禁用、角色变更和退出后及时使会话失效。
- 上传接口限制类型、大小和文件名。
- 导出接口执行权限校验并记录日志。
- 服务端统一校验请求参数，不能依赖前端校验。
- 生产密钥、数据库连接和 Token 密钥只保存在服务器环境变量中。

## 28. 非功能要求

### 28.1 可用性

- 表格具备加载、空数据和失败状态。
- 表单防止重复提交。
- 状态切换失败后恢复原值。
- 删除、禁用和状态流转前进行确认。
- 页面刷新后能够恢复当前会话和菜单。

### 28.2 性能

- 页面使用路由懒加载。
- Element Plus 图标按需引入。
- ECharts 使用按需模块，避免完整打包。
- 列表默认分页，不一次返回全部业务数据。
- 搜索输入使用确认查询或防抖。

### 28.3 兼容性

- 支持现代 Chrome、Edge 和 Firefox。
- 桌面端为主要使用场景。
- 窄屏下保证表格可横向滚动，表单和弹窗不溢出。

### 28.4 编码

- 所有源码和文档使用 UTF-8 无 BOM。
- 中文注释和文案保持可读，不允许乱码。

## 30. 验收标准

### 30.1 认证验收

- 登录请求中不存在可直接读取的明文密码。
- 正确账号可以登录，错误账号有明确提示。
- 禁用管理员不能登录。
- Token 失效后系统正确退出。
- 页面刷新后重新验证用户和权限。

### 30.2 权限验收

- 四个预置角色看到不同菜单。
- 无权限路由进入 `403` 页面。
- 无权限按钮不可见。
- 手动调用无权限接口返回 `403`。
- 角色权限修改后重新登录能够生效。

### 30.3 业务验收

- 商品、分类、订单、用户和门店列表均读取真实接口。
- 商品新增、编辑、上下架和删除能够正确执行。
- 分类关联商品时禁止删除。
- 订单只能按合法状态流转。
- 用户禁用后不能继续登录。
- 后台修改商品和订单后，用户端能够看到变化。

### 30.4 系统验收

- 重要写操作能够在操作日志中查询。
- 上传图片能够通过 HTTPS 地址访问。
- 导出文件名称和内容正确。
- 所有列表具备分页和筛选。
- 生产构建无阻断错误。
- 核心接口具备自动化测试。

## 32. 最终效果

普通用户在用户端注册、浏览商品、维护地址并创建订单。后台工作人员通过加密登录进入管理系统，根据角色获得对应菜单和按钮权限。

商品运营维护商品、分类、图片、规格和上下架状态；订单客服查看顾客和订单并推进订单状态；门店管理员维护门店信息和营业状态；超级管理员维护后台账号、角色、菜单和权限。

所有关键操作由后端校验权限并记录日志。工作台展示真实业务统计，后台数据修改能够同步反映到用户端。

最终系统规模保持克制，但完整具备认证、会话、动态菜单、角色权限、按钮权限、业务 CRUD、状态流转、文件上传、图表、导出、操作日志、错误处理、测试和部署能力。
